# Catalog Slice Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the disposable category reference slice with an idiomatic Go Catalog that preserves the canonical TypeScript business behavior.

**Architecture:** One `internal/catalog` vertical slice owns Catalog commands, projections, transactional authorization, idempotency, and authoritative Audit Events. PostgreSQL/sqlc provide persistence and locking; Echo adapters expose behavior-specific REST routes and separate capability-safe read models.

**Tech Stack:** Go 1.26, Echo v4, PostgreSQL, `database/sql` with pgx/v5, sqlc, `google/uuid`, bcrypt through `internal/auth`, Testify, Swagger.

**Spec:** `docs/superpowers/specs/2026-09-10-catalog-slice-design.md`

## Global Constraints

- Canonical domain documentation wins over contradictory TypeScript runtime behavior.
- All Catalog entity IDs are UUIDs generated by PostgreSQL.
- Prices and surcharges are whole-VND `BIGINT` values bounded from zero or one through `2_147_483_647` as specified.
- Sizes store absolute selling prices, never adjustments.
- Every mutation requires an actor-scoped UUID `request_id`.
- Price-sensitive commands require current `catalog.change_price` authority and a fresh Manager PIN, including replay attempts.
- Every successful state change and its Audit Event commit in one transaction; replays and same-state Availability no-ops do not duplicate events.
- Availability and Retirement remain separate concepts; no destructive Catalog API is permitted.
- Sellable, management, and availability projections must not leak fields across capability boundaries.
- Phase 2 does not implement Sales draft or Commit behavior.
- Follow TDD: observe each new test fail before writing the production behavior.
- Run integration packages with `-p 1` because they share one test database.
